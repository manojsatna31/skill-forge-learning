Phase 2 · Foundations

📊 Day 1 – Big‑O Notation (The Language of Efficiency)

🎯 Why this matters: In interviews, you will always be asked about complexity. Big-O is how you prove you can write code that scales. A correct O(n²) solution is often rejected in favour of an O(n) solution.

Concept: Big-O Notation describes how the runtime of an algorithm grows as the input size (n) increases. It ignores constants and focuses on the dominant term.

📈 1. The Complexity Hierarchy (From Fastest to Slowest)

Notation Name Example Code Scale (n=1,000)
O(1) Constant array[0] 1 operation
O(log n) Logarithmic Binary Search ~10 ops (log₂1000)
O(n) Linear for i in range(n) 1,000 ops
O(n log n) Linearithmic Merge Sort ~10,000 ops
O(n²) Quadratic Nested Loops 1,000,000 ops
O(2ⁿ) Exponential Fibonacci (Naive) 2¹⁰⁰⁰ (Impossible)

🧠 2. Understanding Each Complexity (With Code)

🔹 O(1) – Constant Time

What it means: The algorithm takes the same amount of time regardless of input size.

def get_first_element(arr):
    return arr[0]  # Takes 1 step, whether arr has 10 or 1,000,000 elements

Interview Context: HashMap lookups (dict.get()) and Array indexing are classic O(1). If you can use a hash map, you often turn an O(n) problem into O(1).

🔹 O(log n) – Logarithmic Time

What it means: The algorithm repeatedly divides the input in half (like searching a phone book).

def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target: return mid
        elif arr[mid] < target: left = mid + 1
        else: right = mid - 1
    return -1
# For n=1,000,000, it takes ~20 steps (log₂1,000,000 ≈ 20)
📌 Remember: If you see "sorted array", think Binary Search → O(log n).

🔹 O(n) – Linear Time

What it means: The runtime grows proportionally with the input size.

def find_max(arr):
    max_val = arr[0]
    for num in arr:  # Visits every element exactly once
        if num > max_val:
            max_val = num
    return max_val

Interview Context: Single loop over data is usually O(n). It's often the "best achievable" if you must look at every element.

🔹 O(n log n) – Linearithmic Time

What it means: The algorithm does a logarithmic operation (like divide and conquer) for each element. This is the gold standard for sorting.

# Merge Sort, Quick Sort (average case)
# For n=1,000,000, it takes ~20 million operations (n * log₂n), which is manageable.

Interview Context: Most efficient sorting algorithms are O(n log n). If you need to sort, you can't do better than this (for comparison sorts).

🔹 O(n²) – Quadratic Time (Warning Zone)

What it means: Nested loops. For n=10,000, this runs 100,000,000 times – usually unacceptable.

def find_duplicates(arr):
    for i in range(len(arr)):
        for j in range(i+1, len(arr)):  # Nested loop
            if arr[i] == arr[j]:
                return True
    return False
# Can often be optimised to O(n) using a Set
⚠️ Warning: If your solution has nested loops, always ask: "Can I use a HashMap/Set to make this O(n)?"

💾 3. Space Complexity (The Hidden Cost)

It's not just about time. Space complexity measures how much extra memory your algorithm uses.

  • O(1) Space: Uses a fixed amount of memory (e.g., a few variables).
  • O(n) Space: Uses memory proportional to input (e.g., storing results in an array, recursive call stack).
  • O(n²) Space: Rare, but possible (e.g., 2D DP tables).
def fibonacci_memo(n, memo={}):
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fibonacci_memo(n-1, memo) + fibonacci_memo(n-2, memo)
    return memo[n]
# Space: O(n) because the memo dictionary stores n entries.

📊 4. Asymptotic Analysis (Best, Average, Worst Case)

Big-O usually describes the worst case. But sometimes we also talk about Best (Ω) and Average (Θ).

Algorithm Best (Ω) Average (Θ) Worst (O)
Quick Sort Ω(n log n) Θ(n log n) O(n²)
Merge Sort Ω(n log n) Θ(n log n) O(n log n)
Binary Search Ω(1) Θ(log n) O(log n)
Linear Search Ω(1) Θ(n) O(n)
📌 Interview Tip: When asked about complexity, always specify which case you're talking about. "This is O(n) in the worst case, but if the array is already sorted, it's O(1)."

🔄 Day 2 – Recursion (The Foundation of Trees, Graphs & DP)

🎯 Why this matters: Recursion is the backbone of Trees, Graphs, Backtracking, and Dynamic Programming. If you don't master recursion, you will struggle with 60% of DSA problems.

📖 1. What is Recursion?

Definition: A function that calls itself. It is a way of solving a problem by breaking it down into smaller, identical subproblems.

The Two Laws of Recursion:

  • 1. Base Case: The condition that stops the recursion (the "exit").
  • 2. Recursive Case: The part where the function calls itself with a smaller input.

🔹 Classic Example: Factorial

def factorial(n):
    # 1. Base Case
    if n <= 1:
        return 1
    # 2. Recursive Case
    return n * factorial(n - 1)

# factorial(5) = 5 * 4 * 3 * 2 * 1 = 120

🧠 2. How Recursion Works (The Call Stack)

Every recursive call creates a new frame on the call stack. The stack holds the state of each function call (local variables, return address).

# Visualising the Call Stack for factorial(3)

────────────────────────────────

factorial(3) → 3 * factorial(2)

└── factorial(2) → 2 * factorial(1)

└── factorial(1) → Base Case (returns 1)

────────────────────────────────

# Unwinding the Stack

factorial(1) = 1

factorial(2) = 2 * 1 = 2

factorial(3) = 3 * 2 = 6

────────────────────────────────

📌 Final Output: 6

📌 Key Insight: Recursion uses the call stack to keep track of intermediate results. This is why deep recursion can cause a Stack Overflow (Python default limit ~1000).

💡 3. When to Use Recursion

✅ Use Recursion When:
  • The problem can be broken into smaller sub‑problems (like Divide & Conquer).
  • You are working with Trees or Graphs (DFS).
  • You need to implement Backtracking (N‑Queens, Maze).
  • The problem is naturally recursive (e.g., Factorial, Fibonacci).
❌ Avoid Recursion When:
  • The depth of recursion will exceed the stack limit (Python ~1000).
  • You can easily solve it with a simple iterative loop.
  • Performance is critical and function call overhead matters (rare).

🛠️ 4. The Three Steps to Write Any Recursive Function

  1. Define the Base Case: What is the simplest input that doesn't need recursion? (e.g., n == 0 or arr is empty).
  2. Define the Recursive Case: How do you reduce the problem to a smaller version of itself?
  3. Trust the Recursion: Assume the recursive call works for the smaller input, and build the result from it.

🧪 5. Common Pitfalls & How to Avoid Them

❌ No Base Case 
def bad(n):
    return n * bad(n-1)  # Infinite recursion!
➜ Fix: Always define the exit condition first.
❌ Stack Overflow 
fibonacci(1000)  # Recursion depth exceeded!
➜ Fix: Use iteration, or add sys.setrecursionlimit() (rarely recommended).
❌ Recomputing Subproblems (Naive Fibonacci) 
fib(5) → fib(4) + fib(3)
        fib(4) → fib(3) + fib(2)  # fib(3) computed twice!
➜ Fix: Use Memoization (caching) – store results in a HashMap.
❌ Forgetting to Return 
def sum(n):
    if n == 0: return 0
    n + sum(n-1)  # Missing 'return'! Returns None
➜ Fix: Always return the recursive result.

📝 6. Problem Solving Exercise

🎯 Challenge Write a recursive function to calculate the sum of digits of a number (e.g., sum_digits(123) = 1+2+3 = 6).

  • Base Case: If n == 0, return 0.
  • Recursive Case: return (n % 10) + sum_digits(n // 10).
def sum_digits(n):
    if n == 0:
        return 0
    return (n % 10) + sum_digits(n // 10)

# sum_digits(123) → 3 + sum_digits(12) → 3 + 2 + sum_digits(1) → 3+2+1+0 = 6

🧠 Remember This for Interviews

  • Recursion is essential for Tree/Graph traversals (DFS).
  • Memoization (adding a cache) turns exponential recursion into linear DP.
  • Always start with the Base Case when writing a recursive function.
  • If you can solve it with a Stack (iterative), you can solve it with recursion (and vice versa).

Data Structures

📦 Day 3 – Arrays & Prefix Sum

🎯 Why this matters: Arrays are the most fundamental data structure. Prefix Sum is a powerful technique that turns O(n²) range-sum queries into O(1). This pattern appears in countless interview problems.

📖 1. The Array

Definition: A contiguous block of memory storing elements of the same type. Access is O(1), insertion/deletion is O(n).

🔹 Array Operations

Operation Time Example
Access O(1) arr[i]
Search O(n) Linear scan
Insert (end) O(1)* append()
Insert (middle) O(n) insert()
Delete O(n) pop(i)

* Amortised O(1) for dynamic arrays like Python lists.

🧠 2. Prefix Sum (The Game Changer)

What it is: Pre‑compute an array where prefix[i] stores the sum of all elements from arr[0] to arr[i-1].

Why it's powerful: It allows you to calculate the sum of any subarray arr[l:r] in O(1) time instead of O(n).

def prefix_sum(arr):
    pref = [0] * (len(arr) + 1)
    for i in range(len(arr)):
        pref[i+1] = pref[i] + arr[i]
    return pref

# Example:
arr = [1, 2, 3, 4, 5]
pref = prefix_sum(arr)
# pref = [0, 1, 3, 6, 10, 15]
# Sum of arr[1:4] = pref[4] - pref[1] = 10 - 1 = 9

📝 3. Problem: Maximum Subarray Sum (Kadane's Algorithm)

Problem: Given an array of integers (can be negative), find the contiguous subarray with the largest sum.

  • Brute Force: Check all subarrays (O(n²)).
  • Kadane's Algorithm: Keep a running sum. If the running sum becomes negative, reset it to 0. Track the maximum.
💡 Show Solution (Kadane's Algorithm) 
def max_subarray_sum(nums):
    max_sum = float('-inf')
    current_sum = 0
    for num in nums:
        current_sum += num
        if current_sum > max_sum:
            max_sum = current_sum
        if current_sum < 0:
            current_sum = 0
    return max_sum

# Example: [-2,1,-3,4,-1,2,1,-5,4] → 6 (subarray [4,-1,2,1])

Why it works: If a subarray has a negative prefix, it will only drag down the sum, so we discard it and start fresh.

✅ Task Solve: Given an array, find the subarray with the maximum product (not sum).

💡 Show Solution (Maximum Product Subarray) 
def max_product_subarray(nums):
    max_prod = nums[0]
    min_prod = nums[0]
    result = nums[0]
    for i in range(1, len(nums)):
        if nums[i] < 0:
            max_prod, min_prod = min_prod, max_prod
        max_prod = max(nums[i], max_prod * nums[i])
        min_prod = min(nums[i], min_prod * nums[i])
        result = max(result, max_prod)
    return result

📦 Day 4 – Two Pointers

🎯 Why this matters: Two Pointers is the key to solving many array/string problems in O(n) time without extra space. It's used in "Three Sum", "Trapping Rain Water", and "Palindrome" checks.

📖 1. The Pattern

Setup: Place two pointers (left and right) at the beginning and end of the array. Move them towards each other based on a condition.

🔹 Classic Template

left = 0
right = len(arr) - 1
while left < right:
    if condition:
        left += 1
    else:
        right -= 1

📝 2. Problem: Pair Sum (Sorted Array)

Problem: Given a sorted array and a target, find if there exists a pair that sums to the target.

💡 Show Solution 
def two_sum_sorted(arr, target):
    left, right = 0, len(arr) - 1
    while left < right:
        current_sum = arr[left] + arr[right]
        if current_sum == target:
            return (left, right)
        elif current_sum < target:
            left += 1
        else:
            right -= 1
    return None

📝 3. Problem: Remove Duplicates (In‑Place)

Problem: Given a sorted array, remove duplicates in‑place and return the new length.

💡 Show Solution 
def remove_duplicates(arr):
    if not arr: return 0
    write = 1
    for read in range(1, len(arr)):
        if arr[read] != arr[read - 1]:
            arr[write] = arr[read]
            write += 1
    return write

✅ Task Solve: "Trapping Rain Water" – given an array of heights, calculate how much water can be trapped.

💡 Show Solution (Two Pointers) 
def trap(height):
    if not height: return 0
    left, right = 0, len(height) - 1
    left_max = height[left]
    right_max = height[right]
    water = 0
    while left < right:
        if left_max < right_max:
            left += 1
            left_max = max(left_max, height[left])
            water += left_max - height[left]
        else:
            right -= 1
            right_max = max(right_max, height[right])
            water += right_max - height[right]
    return water

📦 Day 5 – Strings

🎯 Why this matters: Strings are one of the most frequently tested topics. They are essentially arrays of characters, but with additional nuances like immutability and Unicode.

📖 1. String Fundamentals

  • Immutability: In Python/Java, strings cannot be changed in‑place. New strings are created on modification.
  • Common operations: len(), s[i] (access), s[start:end] (slicing), in (membership).
  • Pattern: Sliding Window + HashMaps are extremely common on strings (substring problems).

📝 2. Problem: Valid Palindrome

Problem: Check if a string is a palindrome (ignoring non‑alphanumeric characters and case).

💡 Show Solution 
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True

📝 3. Problem: Longest Substring Without Repeating Characters

Problem: Find the length of the longest substring with no repeating characters.

💡 Show Solution (Sliding Window) 
def longest_unique_substr(s):
    start = 0
    max_len = 0
    seen = {}
    for end, ch in enumerate(s):
        if ch in seen and seen[ch] >= start:
            start = seen[ch] + 1
        seen[ch] = end
        max_len = max(max_len, end - start + 1)
    return max_len

✅ Task Solve: "Longest Palindromic Substring".

💡 Show Solution (Expand Around Center) 
def longest_palindrome(s):
    def expand(left, right):
        while left >= 0 and right < len(s) and s[left] == s[right]:
            left -= 1
            right += 1
        return s[left+1:right]
    result = ""
    for i in range(len(s)):
        odd = expand(i, i)
        even = expand(i, i+1)
        result = max([result, odd, even], key=len)
    return result

📦 Day 6 – HashMaps (Dictionaries)

🎯 Why this matters: HashMaps are the most powerful tool in your DSA toolkit. They turn O(n) lookups into O(1). If you ever have nested loops, ask yourself: "Can I replace this inner loop with a HashMap?"

📖 1. The HashMap

  • Key‑Value Storage: dict in Python, HashMap in Java.
  • Average Operations: O(1) for insertion, deletion, and lookup.
  • Use Cases: Frequency counting, grouping, memoization, and two‑sum problems.

📝 2. Problem: Two Sum

Problem: Given an array of integers, return the indices of two numbers that add up to a target.

💡 Show Solution 
def two_sum(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i
    return None

📝 3. Problem: Frequency Count

Problem: Given an array, find the element that appears more than n/2 times (majority element).

💡 Show Solution 
def majority_element(nums):
    freq = {}
    for num in nums:
        freq[num] = freq.get(num, 0) + 1
        if freq[num] > len(nums) // 2:
            return num
    return None

✅ Task Solve: "Group Anagrams" – group words that are anagrams of each other.

💡 Show Solution 
def group_anagrams(strs):
    from collections import defaultdict
    groups = defaultdict(list)
    for s in strs:
        key = ''.join(sorted(s))
        groups[key].append(s)
    return list(groups.values())

📦 Day 7 – Linked Lists (Singly)

🎯 Why this matters: Linked Lists are the foundation for more complex data structures (stacks, queues, graphs). They are frequently tested in interviews because they test pointer manipulation skills.

📖 1. The Node

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

📝 2. Problem: Reverse a Linked List

Problem: Reverse a singly linked list.

💡 Show Solution (Iterative) 
def reverse_list(head):
    prev = None
    curr = head
    while curr:
        next_temp = curr.next
        curr.next = prev
        prev = curr
        curr = next_temp
    return prev

Explanation:

  • prev: Initially None (the new tail).
  • curr: Starts at head.
  • Step: Store next_temp → Reverse pointer curr.next = prev → Move prev = curr → Move curr = next_temp.

📝 3. Problem: Find the Middle of a Linked List

💡 Show Solution (Tortoise & Hare) 
def middle_node(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow

Explanation: Fast moves two steps for every one step of slow. When fast reaches the end, slow is at the middle.

✅ Task Solve: "Merge Two Sorted Linked Lists".

💡 Show Solution (Recursive + Iterative) 
def merge_two_lists(l1, l2):
    dummy = ListNode()
    tail = dummy
    while l1 and l2:
        if l1.val < l2.val:
            tail.next = l1
            l1 = l1.next
        else:
            tail.next = l2
            l2 = l2.next
        tail = tail.next
    tail.next = l1 or l2
    return dummy.next

📦 Day 8 – Linked Lists (Cycle Detection)

🎯 Why this matters: Cycle detection is a classic interview problem (often asked as "Detect a loop in a linked list"). It tests your understanding of two pointers and memory efficiency.

📖 1. Floyd's Tortoise and Hare Algorithm

Idea: Use two pointers – a slow pointer (tortoise) that moves one step at a time, and a fast pointer (hare) that moves two steps. If they meet, there is a cycle.

# Visualisation

────────────────────────────────

1 → 2 → 3 → 4 → 5 → 6

↑ ↓

9 ← 8 ← 7

────────────────────────────────

slow moves 1 step, fast moves 2 steps → they meet inside the cycle.

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast:
            return True
    return False

📝 2. Problem: Find the Start of the Cycle

Problem: Given a linked list with a cycle, return the node where the cycle begins.

💡 Show Solution 
def detect_cycle_start(head):
    # First, find if a cycle exists
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast:
            break
    else:
        return None  # No cycle

    # Move slow to head, keep fast at meeting point
    slow = head
    while slow != fast:
        slow = slow.next
        fast = fast.next
    return slow

Why it works: The distance from head to cycle start equals the distance from meeting point to cycle start (mathematical property).

✅ Task Solve: "Remove the Cycle" – break the cycle by setting the next pointer of the last node to None.

💡 Show Solution 
def remove_cycle(head):
    # Find cycle start first
    start = detect_cycle_start(head)
    if not start: return
    # Find the node that points to start (the tail)
    tail = start
    while tail.next != start:
        tail = tail.next
    tail.next = None

📝 4. Problem: N‑Queens

Problem: Place N queens on an N×N chessboard so that no two queens attack each other. Return all distinct solutions.

💡 Show Solution 
def solve_n_queens(n):
    result = []
    board = [['.'] * n for _ in range(n)]
    cols = set()
    diag1 = set()  # r + c
    diag2 = set()  # r - c

    def backtrack(r):
        if r == n:
            result.append([''.join(row) for row in board])
            return
        for c in range(n):
            if c in cols or (r+c) in diag1 or (r-c) in diag2:
                continue
            board[r][c] = 'Q'
            cols.add(c)
            diag1.add(r+c)
            diag2.add(r-c)
            backtrack(r+1)
            board[r][c] = '.'
            cols.remove(c)
            diag1.remove(r+c)
            diag2.remove(r-c)

    backtrack(0)
    return result

Why it works: We place queens row by row. The constraints ensure no two queens share a column or diagonal. When we reach row N, we've found a valid solution.

def has_cycle_directed(graph):
    # 0 = unvisited, 1 = visiting, 2 = visited
    state = {node: 0 for node in graph}

    def dfs(node):
        if state[node] == 1: return True   # cycle
        if state[node] == 2: return False  # already processed
        state[node] = 1
        for neighbor in graph[node]:
            if dfs(neighbor): return True
        state[node] = 2
        return False

    for node in graph:
        if dfs(node): return True
    return False

Why it works: If we encounter a node that is currently in the recursion stack (state = 1), we've found a cycle.

🕸️ Day 23 – Topological Sort (Kahn's Algorithm)

🎯 Why this matters: Topological sort is used for task scheduling (course prerequisites), build systems (Makefiles), and dependency resolution (package managers).

📖 1. Topological Sort (BFS – Kahn's Algorithm)

  • Idea: A linear ordering of vertices such that for every edge u → v, u comes before v.
  • Steps:
    • Compute indegree for all nodes.
    • Add nodes with indegree 0 to a queue.
    • While queue is not empty: pop node, add to result, reduce indegree of its neighbours. If any neighbour's indegree becomes 0, add it to the queue.
  • If result length != V, there is a cycle.

# Kahn's Algorithm Example

────────────────────────────────

Courses: 0 → 1, 2

1 → 3

2 → 3

────────────────────────────────

Indegrees: 0:0, 1:1, 2:1, 3:2

Order: 0 → 1 → 2 → 3 (or 0 → 2 → 1 → 3)

from collections import deque

def topological_sort(graph):
    indegree = {node: 0 for node in graph}
    for node in graph:
        for neighbor in graph[node]:
            indegree[neighbor] += 1

    q = deque([n for n in graph if indegree[n] == 0])
    result = []

    while q:
        node = q.popleft()
        result.append(node)
        for neighbor in graph[node]:
            indegree[neighbor] -= 1
            if indegree[neighbor] == 0:
                q.append(neighbor)

    return result if len(result) == len(graph) else []  # [] means cycle

        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

        node = self.root
        for ch in word:
            if ch not in node.children:
                return False
            node = node.children[ch]
        return node.is_end

        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return False
            node = node.children[ch]
        return True

def coin_change(coins, amount):
    memo = {}
    def dp(remaining):
        if remaining == 0: return 0
        if remaining < 0: return float('inf')
        if remaining in memo: return memo[remaining]
        best = float('inf')
        for coin in coins:
            best = min(best, 1 + dp(remaining - coin))
        memo[remaining] = best
        return best
    result = dp(amount)
    return result if result != float('inf') else -1

Why it works: dp(remaining) returns the minimum coins to make the remaining amount. We try each coin, subtract it, and recurse. The memo prevents recomputing for the same remaining amount.

def knapsack(weights, values, capacity):
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for w in range(1, capacity + 1):
            if weights[i-1] <= w:
                dp[i][w] = max(dp[i-1][w], values[i-1] + dp[i-1][w - weights[i-1]])
            else:
                dp[i][w] = dp[i-1][w]
    return dp[n][capacity]

def longest_k_distinct(s, k):
    left = 0
    max_len = 0
    freq = {}
    for right, ch in enumerate(s):
        freq[ch] = freq.get(ch, 0) + 1
        while len(freq) > k:
            left_char = s[left]
            freq[left_char] -= 1
            if freq[left_char] == 0:
                del freq[left_char]
            left += 1
        max_len = max(max_len, right - left + 1)
    return max_len

    if not s or not t: return ""
    from collections import Counter
    need = Counter(t)
    have = {}
    left = 0
    required = len(need)
    formed = 0
    min_len = float('inf')
    result = ""

    for right, ch in enumerate(s):
        have[ch] = have.get(ch, 0) + 1
        if ch in need and have[ch] == need[ch]:
            formed += 1

        while left <= right and formed == required:
            if right - left + 1 < min_len:
                min_len = right - left + 1
                result = s[left:right+1]
            # Shrink from left

            have[left_char] -= 1
            if left_char in need and have[left_char] < need[left_char]:
                formed -= 1
            left += 1
    return result

Why it works: We expand the right pointer until we have all required characters. Then we shrink from the left to find the smallest window that still contains all characters.

        max_freq = max(max_freq, freq[ch])
        # If the window size minus the most frequent character > k, shrink
        if (right - left + 1) - max_freq > k:
            left_char = s[left]
            freq[left_char] -= 1
            left += 1
        max_len = max(max_len, right - left + 1)
    return max_len

🎯 Why this matters: Backtracking is the systematic way to explore all possibilities. It's used in generating combinations, permutations, and solving constraint satisfaction problems (N-Queens, Sudoku). The key is the "decision tree" – include/exclude, or try each option.

📝 1. Problem: Permutations II (Duplicates)

💡 Show Solution 
def permute_unique(nums):

    result = []
    visited = [False] * len(nums)
    def backtrack(path):
        if len(path) == len(nums):
            result.append(path[:])
            return
        for i in range(len(nums)):
            if visited[i] or (i > 0 and nums[i] == nums[i-1] and not visited[i-1]):

    return result

🕸️ Day 39 – Dijkstra's Algorithm

🎯 Why this matters: Dijkstra is the most important shortest-path algorithm for weighted graphs (non‑negative weights). It's used in GPS navigation, network routing, and any optimization problem.

📖 1. Dijkstra's Algorithm (Heap‑Based)

  • Idea: Maintain a min‑heap of (distance, node). Start with (0, start). For each popped node, relax its neighbours.
  • Complexity: O((V+E) log V).
import heapq

def dijkstra(graph, start):
    distances = {node: float('inf') for node in graph}
    distances[start] = 0
    heap = [(0, start)]
    while heap:
        current_dist, node = heapq.heappop(heap)
        if current_dist > distances[node]:
            continue
        for neighbor, weight in graph[node]:
            distance = current_dist + weight
            if distance < distances[neighbor]:
                distances[neighbor] = distance
                heapq.heappush(heap, (distance, neighbor))
    return distances

        else:

        px, py = find(x), find(y)
        if px == py: return
        if rank[px] < rank[py]:
            parent[px] = py
        elif rank[px] > rank[py]:
            parent[py] = px
        else:
            parent[py] = px
            rank[px] += 1
        count -= 1
    for x, y in positions:
        if (x,y) in parent:
            result.append(count)
            continue
        parent[(x,y)] = (x,y)
        rank[(x,y)] = 0
        count += 1
        for dx, dy in [(1,0),(-1,0),(0,1),(0,-1)]:
            nx, ny = x+dx, y+dy
            if (nx,ny) in parent:
                union((x,y), (nx,ny))
        result.append(count)
    return result

🚀 Case Study 1: URL Shortener (TinyURL)

📖 Problem Statement

Design a system that converts long URLs into short, unique URLs (like tinyurl.com/abc123). Support:

  • encode(originalURL) → Returns a short URL.
  • decode(shortURL) → Returns the original URL.

Real-World Context: Used by Bitly, TinyURL, and every social media platform to save characters and track clicks.

🧠 Scenarios to Consider

  • Collision: Two different URLs generate the same short code.
  • Scale: Billions of URLs need to be stored (Twitter had ~6000 writes/sec).
  • Custom Short URLs: Users want my.link/custom instead of random codes.
  • Expiry: Short URLs should expire after a certain time (optional).

🔍 Approach 1: Brute Force (Random Hash)

Idea: Generate a random 6‑character string (62⁶ ≈ 56B combinations). Check a database for collisions.

import random, string

class URLShortener:
    def __init__(self):
        self.url_map = {}
        self.base_url = "http://tinyurl.com/"

    def _generate_code(self):
        return ''.join(random.choices(string.ascii_letters + string.digits, k=6))

    def encode(self, long_url):
        code = self._generate_code()
        while code in self.url_map:  # Collision check
            code = self._generate_code()
        self.url_map[code] = long_url
        return self.base_url + code

    def decode(self, short_url):
        code = short_url.split('/')[-1]
        return self.url_map.get(code, None)

Complexity: O(1) average, but collisions become likely as the number of URLs grows. Non‑deterministic.

🚀 Case Study 2: LRU Cache (Least Recently Used)

📖 Problem Statement

Design a data structure that caches key‑value pairs with a fixed capacity. When full, it evicts the least recently used item. Support O(1) operations:

  • get(key) – Return value, mark as recently used.
  • put(key, value) – Insert/update. Evict LRU if capacity exceeded.

Real-World Context: Web browsers, database query caches, CDNs, and OS page replacement.

🧠 Scenarios

  • Capacity Full: Which item to evict? (LRU)
  • Frequent Access: How to update "recently used" status efficiently?
  • Concurrent Access: Multiple threads reading/writing the cache.
  • Large Cache: Keep O(1) operations even with millions of items.

🔍 Approach 1: Brute Force (List)

Idea: Store in a list. On get(), scan. On put(), append and pop front if full.

class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.cache = []  # [key, value]

    def get(self, key):
        for i, (k, v) in enumerate(self.cache):
            if k == key:
                self.cache.append(self.cache.pop(i))
                return v
        return -1

    def put(self, key, value):
        for i, (k, v) in enumerate(self.cache):
            if k == key:
                self.cache[i] = [key, value]
                self.cache.append(self.cache.pop(i))
                return
        if len(self.cache) >= self.capacity:
            self.cache.pop(0)
        self.cache.append([key, value])

Complexity: O(n) for both – too slow for production.

Idea: HashMap for O(1) lookups. Doubly Linked List to maintain usage order (most recent at head, least at tail).

        self.cache = {}
        self.head = Node()
        self.tail = Node()
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_to_head(self, node):
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key):
        if key not in self.cache: return -1
        node = self.cache[key]
        self._remove(node)
        self._add_to_head(node)
        return node.value

    def put(self, key, value):
        if key in self.cache:
            node = self.cache[key]
            node.value = value
            self._remove(node)
            self._add_to_head(node)
        else:
            if len(self.cache) >= self.capacity:
                lru = self.tail.prev
                self._remove(lru)
                del self.cache[lru.key]
            new_node = Node(key, value)
            self.cache[key] = new_node
            self._add_to_head(new_node)

Complexity: O(1) for both – optimal.

💡 Key Takeaways
  • HashMap gives O(1) lookups; Doubly Linked List gives O(1) insertion/deletion anywhere.
  • This is a classic hybrid data structure – combining two simple structures to solve a complex problem.
  • Thread safety is a real concern; in production, add locks or use a concurrent version.

📖 Problem Statement

Design a simplified Twitter where users can post, follow/unfollow, and get the 10 most recent tweet IDs from themselves and their followees.

Real-World Context: Twitter, Facebook, and Instagram face this exact challenge at massive scale.

🧠 Scenarios

  • Fan‑out vs Pull: Pre‑compute feeds (fan‑out on write) OR compute on read (pull)?
  • Read/Write Ratio: Twitter had ~300,000 reads/second vs 6,000 writes/second (50:1).

🔍 Approach 1: Brute Force (Scan All Tweets)

Idea: Store all tweets. On feed request, scan, filter by followees, sort, and take top 10.

Complexity: O(n log n) where n is total tweets – impossible at scale.

⚡ Approach 2: Better – Per‑User Lists + Max Heap

Idea: Store tweets per user. On feed request, use a Max Heap to merge the most recent tweets from each followee.

import heapq

class Twitter:
    def __init__(self):
        self.tweets = {}  # userId -> list of (timestamp, tweetId)
        self.followers = {}  # userId -> set of followees
        self.time = 0

    def getNewsFeed(self, userId):
        followees = self.followers.get(userId, set()) | {userId}
        heap = []

        for f in followees:
            if f in self.tweets and self.tweets[f]:
                last_idx = len(self.tweets[f]) - 1
                timestamp, tweetId = self.tweets[f][last_idx]
                heapq.heappush(heap, (-timestamp, tweetId, f, last_idx - 1))

        result = []
        while heap and len(result) < 10:
            neg_ts, tweetId, user, idx = heapq.heappop(heap)
            result.append(tweetId)
            if idx >= 0:
                timestamp, next_tweet = self.tweets[user][idx]
                heapq.heappush(heap, (-timestamp, next_tweet, user, idx - 1))

        return result

Complexity: O(k log k) where k = number of followees – much faster.

🏆 Best Approach: Hybrid (Fan‑out on Write for Regular Users + Pull for Celebrities)

Idea: For users with few followers (<1000), pre‑compute feed on write (fan‑out). For celebrities (millions of followers), compute feed on read (pull) to avoid 31M inserts per tweet.

💡 Key Takeaways
  • Heaps (Priority Queues) are the key to efficiently merging sorted lists.
  • Real‑world systems use a hybrid approach – fan‑out for regular users, pull for celebrities.

🚀 Case Study 5: Rate Limiter (Hit Counter)

📖 Problem Statement

Design a rate limiter that tracks API requests per user and rejects requests that exceed a quota (e.g., 100 requests per minute).

Real-World Context: Cloudflare, Stripe, AWS API Gateway all implement rate limiting.

🧠 Scenarios

  • Fixed Window: Simple but has "burst at boundary" problem.
  • Sliding Window: More accurate but more memory‑intensive.
  • Token Bucket: Allows bursts up to a limit.
  • Distributed: Must work across multiple servers.

🔍 Approach 1: Fixed Window Counter

Idea: Counter per user per fixed time window (e.g., current minute).

Problem: If 100 requests come at 59.9s and 100 at 60.1s, that's 200 requests in a 2‑second span – burst at boundary.

⚡ Approach 2: Sliding Window Log

Idea: Store a list of timestamps per request. Remove timestamps older than the window, then count.

from collections import deque

class RateLimiter:
    def __init__(self, limit=100):
        self.limit = limit
        self.requests = {}

    def allow(self, user_id):
        now = time.time()
        if user_id not in self.requests:
            self.requests[user_id] = deque()

        while self.requests[user_id] and now - self.requests[user_id][0] > 60:
            self.requests[user_id].popleft()

        if len(self.requests[user_id]) >= self.limit:
            return False

        self.requests[user_id].append(now)
        return True

Complexity: O(1) amortized, but memory grows with request frequency.

🏆 Best Approach: Token Bucket (Distributed with Redis)

Idea: Each user has a "bucket" of tokens. Tokens are added at a fixed rate. Each request consumes one token. Allows bursts up to capacity.

class TokenBucket:
    def __init__(self, capacity=100, refill_rate=1):
        self.capacity = capacity
        self.refill_rate = refill_rate
        self.tokens = capacity
        self.last_refill = time.time()

    def allow(self):
        now = time.time()
        elapsed = now - self.last_refill
        self.tokens = min(self.capacity, self.tokens + elapsed * self.refill_rate)
        self.last_refill = now

        if self.tokens >= 1:
            self.tokens -= 1
            return True
        return False
💡 Key Takeaways
  • Fixed window is the simplest but has the boundary burst problem.
  • Sliding window is more accurate but uses more memory.
  • Token bucket is the most popular for API rate limiting because it allows healthy bursts.
  • In production, use Redis to store state for distributed rate limiting.

  • Different spot sizes: Small (motorcycle), Medium (car), Large (bus/truck).
  • Entry/exit points.
  • Parking a vehicle → Assign a spot.
  • Exiting → Free the spot and calculate the fee.

Real-World Context: Shopping malls, airports, office buildings.

🧠 Scenarios

  • Spot Assignment: Find the nearest available spot of the right size.
  • Multiple Vehicle Types: A car can park in Medium or Large, but not Small.
  • Reservations: (Optional) Pre‑book a spot.
  • Concurrent Access: Multiple cars entering at the same time.

🔍 Approach 1: Brute Force (Linear Scan)

Idea: Store all spots in a list. On parking, scan for the first available spot of the right size.

Complexity: O(n) per park – slow for large lots.

⚡ Approach 2: Better – Separate Queues per Size

Idea: Use a queue (FIFO) for each spot size. The nearest available spot is at the front.

Complexity: O(1) for parking and exiting.

🏆 Best Approach: Priority Queue (Closest First)

Idea: For each spot size, use a min‑heap ordered by (level, spot_number). This always returns the closest spot first.

import heapq

class ParkingLot:
    def __init__(self):
        self.available = {"small": [], "medium": [], "large": []}

    def add_spot(self, level, spot_number, size):
        heapq.heappush(self.available[size], (level, spot_number))

    def park(self, vehicle_size):
        for size in [vehicle_size, "medium", "large"]:
            if self.available[size]:
                level, spot = heapq.heappop(self.available[size])
                return (level, spot)
        return None

Complexity: O(log n) per park – fast and scalable.

💡 Key Takeaways
  • Priority Queues (Heaps) are perfect for "find the closest" problems.
  • Separate data structures per type (vehicle size) makes operations simpler and faster.
  • This tests your ability to choose the right data structure for the right operation.

🚀 Case Study 7: Undo/Redo System

📖 Problem Statement

Design a system that supports undo and redo operations on a text editor or any stateful application.

Real-World Context: Every text editor, image editor, and IDE has undo/redo functionality.

🧠 Scenarios

  • State Storage: How to store state (full copy or diffs)?
  • Memory: Saving a full copy of a 10MB document for each operation is expensive.
  • Undo Limit: Most editors support unlimited undo, but memory is finite.

🔍 Approach 1: Full State Storage

Idea: Store a copy of the entire state after each operation.

Complexity: O(1) time, but O(n*m) memory (n ops * m state size).

⚡ Approach 2: Command Pattern (Diffs)

Idea: Store the commands (operations) rather than the full state. Each command has execute() and undo() methods. Much less memory.

🏆 Best Approach: Two Stacks

Idea: Use two stacks – one for undo (history) and one for redo. Push operations onto the history stack. On undo, pop from history and push onto redo. On redo, pop from redo and push back to history.

class Editor:
    def __init__(self):
        self.undo_stack = []
        self.redo_stack = []

    def perform(self, command):
        command.execute()
        self.undo_stack.append(command)
        self.redo_stack.clear()  # New operation invalidates redo

    def undo(self):
        if self.undo_stack:
            command = self.undo_stack.pop()
            command.undo()
            self.redo_stack.append(command)

    def redo(self):
        if self.redo_stack:
            command = self.redo_stack.pop()
            command.execute()
            self.undo_stack.append(command)
💡 Key Takeaways
  • Command Pattern is the standard for undo/redo in OOP.
  • Two stacks provide a clean, efficient implementation.
  • Memory optimisation is critical – store diffs, not full states, for large documents.

🚀 Case Study 8: University Course Prerequisite Manager

📖 Problem Statement

Given a list of courses and prerequisites, determine if a student can complete all courses (no cycles). Suggest an order in which to take the courses.

Real-World Context: Every university registration system uses this to build degree plans.

🧠 Scenarios

  • Cycle Detection: Course A requires B, B requires A – impossible.
  • Multiple Paths: A student can take courses in different orders.
  • Electives: Not all courses are required.

🔍 Approach 1: Brute Force (DFS)

Idea: Build a graph. Use DFS to detect cycles.

Complexity: O(V + E) – good for detection only.

⚡ Approach 2: Better – Kahn's Algorithm (Topological Sort)

Idea: Use BFS with indegree counting. Returns a valid course order if no cycle exists.

from collections import deque

def find_order(num_courses, prerequisites):
    graph = {i: [] for i in range(num_courses)}
    indegree = [0] * num_courses

    for course, prereq in prerequisites:
        graph[prereq].append(course)
        indegree[course] += 1

    queue = deque([i for i in range(num_courses) if indegree[i] == 0])
    result = []

    while queue:
        course = queue.popleft()
        result.append(course)
        for neighbor in graph[course]:
            indegree[neighbor] -= 1
            if indegree[neighbor] == 0:
                queue.append(neighbor)

    return result if len(result) == num_courses else []

Complexity: O(V + E) – optimal.

💡 Key Takeaways
  • Topological Sort is the core algorithm for dependency resolution.
  • Kahn's Algorithm (BFS) is simpler for cycle detection + order.
  • DFS is more compact but requires careful state tracking.
  • This is exactly LeetCode 207 & 210.

🚀 Case Study 10: File Compression (Huffman Coding)

📖 Problem Statement

Design a file compression system using Huffman Coding – a lossless data compression algorithm. Compress a string to a binary representation and decompress it back.

Real-World Context: ZIP files, JPEG, MP3, and HTTP compression (gzip).

🧠 Scenarios

  • Variable‑length Encoding: Frequent characters get shorter codes.
  • Prefix‑free: No code is a prefix of another (unambiguous decoding).
  • Tree Construction: Need to build the Huffman tree efficiently.

🔍 Approach 1: Fixed‑Length Encoding

Idea: Use 8 bits per character (ASCII). Simple but no compression.

⚡ Approach 2: Better – Huffman Coding

Idea: Build a frequency table. Use a min‑heap (priority queue) to build the Huffman tree.

import heapq
from collections import Counter

class HuffmanNode:
    def __init__(self, char, freq):
        self.char = char
        self.freq = freq
        self.left = None
        self.right = None

    def __lt__(self, other):
        return self.freq < other.freq

def build_huffman_tree(text):
    freq = Counter(text)
    heap = [HuffmanNode(char, f) for char, f in freq.items()]
    heapq.heapify(heap)

    while len(heap) > 1:
        left = heapq.heappop(heap)
        right = heapq.heappop(heap)
        parent = HuffmanNode(None, left.freq + right.freq)
        parent.left = left
        parent.right = right
        heapq.heappush(heap, parent)

    return heap[0]

def generate_codes(node, code="", codes={}):
    if node.char is not None:
        codes[node.char] = code
    else:
        generate_codes(node.left, code + "0", codes)
        generate_codes(node.right, code + "1", codes)
    return codes

Complexity: O(n log n) to build – optimal.

💡 Key Takeaways
  • Priority Queues (Min‑Heaps) are essential for building Huffman trees.
  • Trees represent the hierarchical structure of the encoding.
  • Huffman coding is a classic example of optimal prefix‑free coding.
  • Real‑world compression uses adaptive Huffman or arithmetic coding for better ratios.

🧩 DP Strategy Guide – Master Dynamic Programming

DP is the most feared topic in interviews. But it’s just recursion + caching. This guide gives you a repeatable decision tree to identify DP problems and solve them systematically.

🔍 Step 1: Is it a DP problem?

Ask these 3 questions. If any is true, DP is likely the right approach:

  • 1. Is the problem asking for “maximum”, “minimum”, “number of ways”, or “is it possible”? → Yes, DP.
  • 2. Can the problem be broken into smaller, identical sub‑problems? → Yes, DP.
  • 3. Do you see overlapping sub‑problems? (e.g., Fibonacci recomputes the same values repeatedly) → Yes, DP.

📊 Step 2: DP Decision Tree

Is it asking for min/max, count, or boolean?

└── ▶ Yes → DP is viable

└── Can you define a state dp[i] that depends on previous states?

├── Yes → Memoization (Top‑Down)

│ └── Write recursion with a cache dictionary.

├── Yes → Tabulation (Bottom‑Up)

│ └── Fill an array iteratively from base case to target.

└── Both work → Choose the one you’re most comfortable with.

📝 Step 3: Memoization (Top‑Down) – The “Recursive + Cache” Pattern

def dp_solution(problem):
    memo = {}  # Cache

    def dfs(state):
        # 1. Base Case
        if state == base:
            return base_value
        # 2. Check Cache
        if state in memo:

        # 3. Recursive Case
        result = compute(state, dfs(next_state))

📋 Step 4: Tabulation (Bottom‑Up) – The “Iterative” Pattern

def dp_solution(problem):
    # 1. Create DP table (size n+1, or 2D for multiple dimensions)
    dp = [0] * (n + 1)
    # 2. Base Case
    dp[0] = base_value
    # 3. Fill table iteratively
    for i in range(1, n + 1):
        # Compute dp[i] using previous states (dp[i-1], dp[i-2], etc.)
        dp[i] = compute(dp[i-1], dp[i-2], ...)
    # 4. Return answer
    return dp[n]

Items: Target Sum, Partition Equal Subset.
2. Unbounded Knapsack 
dp[w] = max(dp[w],
dp[w-wt[i]] + val[i])
Coin Change I & II, Rod Cutting.
3. LCS (Longest Common Subsequence) 
if s1[i]==s2[j]:
    dp[i][j] = 1 + dp[i-1][j-1]
else:
    dp[i][j] = max(dp[i-1][j], dp[i][j-1])
Edit Distance, Longest Palindromic Subsequence.
4. LIS (Longest Increasing Subsequence) 
dp[i] = 1 + max(dp[j])
where j < i and arr[j] < arr[i]
Can be optimized to O(n log n) using patience sorting.
5. State Machine DP 
dp[i][hold] = max(dp[i-1][hold],
dp[i-1][!hold] +/- price[i])
Buy/Sell Stock with Cooldown.
6. Matrix DP (Grid) 
dp[i][j] = grid[i][j] +
min(dp[i-1][j], dp[i][j-1])
Minimum Path Sum, Unique Paths.
🚀 DP Recognition: If the problem asks for "maximum/minimum", "number of ways", or "is it possible", and you see overlapping subproblems → use DP (Memoization or Tabulation).

🛠️ 7. Essential Coding Patterns

  • Prefix Sum: pref[i] = pref[i-1] + arr[i]. Subarray sum (i,j) = pref[j] - pref[i-1]. O(1) range queries.
  • Difference Array: For range updates. diff[l] += val; diff[r+1] -= val.
  • Monotonic Stack: Maintain increasing/decreasing stack. Used for "Next Greater Element" and "Largest Rectangle in Histogram".
  • Binary Search: while l <= r: mid = (l+r)//2. If condition, r = mid - 1 else l = mid + 1. Used in O(log n) searches and on "Search in Rotated Sorted Array".
  • Union-Find (Disjoint Set): find() with path compression, union() by rank. Used for cycle detection in undirected graphs and connectivity (Number of Islands, Redundant Connection).

✅ 10. The "Before You Submit" Edge Case Checklist

  • Empty Input: Null array, empty string, 0 nodes (return "" or 0).
  • Single Element: n=1 or n=0. Does your loop logic handle it?
  • Duplicates: Does your algorithm work if all elements are the same? (e.g., Binary Search with duplicates).
  • Negative Numbers: If not explicitly restricted, test negative numbers (especially in array sums).
  • Integer Overflow: In languages like Java, use long for sums or check bounds.
  • Cycle in Graph/Tree: Does your traversal terminate (visited set)?
  • Recursive Depth: Python has recursion limit (~1000). For large trees, use iterative approaches.
🏆 Golden Rule: A candidate who fixes the happy path but fails edge cases is easily rejected. Always run through these 5 mentally before hitting submit!
